Create mission-specific private chats only when a real team is active. Do not start ten empty rooms. Pin the conduct rules, first task, website, help route and privacy disclosure. Limit unreviewed invite distribution; disclose phone-number visibility before optional group invitations.

## Suggested weekly cadence (Africa/Johannesburg)
- Monday evening: **COMMIT** (30m), one named and feasible deliverable.
- Wednesday evening: **UNBLOCK** (45m), pair problems with helpers.
- Friday: **SHOW** (45–60m), demos, evidence and peer critique.
- Optional Saturday: **BUILDER TABLE** (2h), verified public venue and named host.
- Every 14 days: **ODYSSEY REVIEW** (60–90m), commitments vs delivery, decisions and next cycle.

## Mission intake standard
Mission name, owner, problem, intended user, 14-day deliverable, roles, capacity, deadline, acceptance criteria, evidence format, privacy/IP/compensation terms.

**Lifecycle:** PROPOSED → TRIAGED → APPROVED → RECRUITING → ACTIVE → REVIEW → SHIPPED/ITERATE/PAUSED → ARCHIVED.

## Copy-ready routines
- Monday: `MISSION / WHAT I COMMIT / BY WHEN / HELP NEEDED`.
- Wednesday: `GOAL / WHAT I TRIED / EXACT BLOCKER / REQUEST`.
- Friday: `PROMISED / DELIVERED / EVIDENCE LINK / LEARNING / NEXT`.
- Intro: `TRACK / INTEREST / CURRENT SKILL LEVEL / NEXT 7-DAY TASK / I CAN HELP WITH`.
- Evidence review: verify artifact link, acceptance criteria, permissions and what was learned; do not count vague claims as shipped.

## First pilot KPI hypotheses
10–20 approved adults; 3–5 genuine missions; 70% first-week activation; at least one demo tested with an external user. Collect aggregate metrics, not public individual rankings.
